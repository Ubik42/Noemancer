# Noemancer Current Architecture

> Status: Current
> Updated: 2026-08-24
> Authority: system boundaries, ownership, dependency direction and public interaction model.

## System model

```text
Project source: project / scene / prefab / asset descriptors / C# / UI resources
                                  |
                 validated import, schema and cook
                                  |
Authoritative runtime: World + domain services + backend adapters
                                  |
            deterministic semantic projections and evidence
                                  |
 Editor UI / project scripts / CLI / MCP / tests / accessibility
```

There is one authoritative state per domain. The Semantic State Plane is a read/change contract over those authorities; it is not another ECS, scene database, UI tree or middleware mirror.

## Actual build and dependency boundaries

The current CMake graph is deliberately simple:

```text
noemancer_engine     domain data, World and runtime services
        ^
noemancer_editor     editor model and GUI over engine contracts
        ^
noemancer runtime    SDL window/GPU/device adapters and application loop

tools/mcp            separate TypeScript process; discovers and calls the C++ ABI
managed/*            separate .NET contracts and hosted project script runtime
```

Rules:

- Engine code must not depend on Editor or the executable Runtime.
- Editor may depend on Engine; Runtime may compose Engine and Editor.
- MCP does not own domain behavior or duplicate command schemas.
- Managed scripts receive stable values and command buffers, never native handles.
- A future split of `noemancer_engine` into smaller targets must follow proven domain ownership; directory aesthetics alone do not justify build fragmentation.

The previous shorthand `core <- world <- runtime/editor/devtools` described intent but did not match the actual targets and is retired.

## Domain ownership

| Domain | Authority | Stable public boundary | Backend implementation |
|---|---|---|---|
| Scene/World | canonical Scene Document and live World | stable entity/component/property IDs, revisions, source anchors | Flecs, Jolt integration |
| Assets | source descriptors, registry, background Job Queue, thumbnail/repair plans and cook manifests | Asset/Job ID, fingerprint, state, progress, dependency, diagnostic/action and artifact URI | fastgltf/ufbx offline decode, KTX-Software/BasisU, meshoptimizer and lodepng behind adapters; SDL_GPU presentation cache |
| Input | Project `inputActions` document and live Input Action runtime | stable action/source IDs, kind, scale, dead zone, value/edge and revision | SDL3 keyboard/gamepad adapter; project policy never enters the platform adapter |
| Rendering | Render World and engine Render Graph | pass/resource/material/object IDs and evidence | SDL_GPU now; optional native backends later |
| Animation | versioned State Machine and Animation Graph assets plus engine skeleton/clip/player instance state | asset/node/layer/mask/state/transition/parameter/entity/joint IDs and bounded definition/instance/pose/compression evidence | ozz runtime packing, sampling, local-space blending and local-to-model; engine-owned graph/state evaluation; candidate codecs remain private and evidence-gated |
| Audio | Asset/Bus/Voice/Listener and `AudioRenderSnapshot` | engine plain data and status; Runtime-private source catalog | miniaudio Resource Manager/streaming production graph; reference Mixer for Headless |
| UI | project/engine Semantic UI Document, runtime binding and action state | stable node IDs, roles, values, source revision, actions and layout evidence | ImGui shell, RmlUi retained layout/render adapter |
| Scripting | Scene `ManagedScript`, debug session and engine command authority | generated C# values, World View, Command Buffer and bounded DAP state/events | HostFXR/CoreCLR plus netcoredbg DAP transport |
| Packaging | validated Project/Scene/Cook closure and Package Plan | Game Profile, deterministic plan/receipt, artifact identity, license/NOTICE and atomic commit request | host filesystem staging adapter; Shader files close from the verified Manifest rather than build-directory enumeration; no CPack state leaks into Engine |
| Agent | C++ command registry and semantic projections | JSON Schema, Observation/Delta/Plan/Receipt/Evidence | direct CLI/JSONL/MCP adapters |

Third-party handles, pointers, enums and persistence formats do not enter Scene, Prefab, generated C# contracts or transport-facing schemas. Backend-specific optional capabilities are discoverable and fail explicitly when unavailable; the engine does not flatten every backend to the lowest common denominator.

Development-time Sol/Luna subagents are repository collaboration roles, not Runtime Agent objects, MCP adapters or a new domain authority. Their output converges through the same source, schemas and verification rules shown above.

## Semantic State Plane

Every public object uses the appropriate identity rather than one overloaded string:

- stable ID/GUID for identity across rename and move;
- semantic path for current namespace location;
- JSON Pointer for a persisted field;
- source URI plus LSP-style range for source provenance;
- Artifact/Evidence URI for large captures and generated data.

Observations are deterministic, revisioned, ordered and bounded by selector, field mask, depth, count or bytes. Incremental consumers use deltas from a known revision and receive an explicit resync response when history is unavailable.

Mutations use:

```text
Observation -> Plan(base revision, intent, validation) -> Apply -> Receipt
```

Agent and GUI actions must converge on the same domain authority. Public mutations add dry-run, revision checks, atomicity and undo when the domain is authorable. Read-only diagnostics do not need artificial transaction wrappers.

Animation authoring uses `noemancer.animation-graph/0.1` as source authority. The document owns parameters, clip/state-machine/Blend 1D nodes, ordered override-then-additive layers, named joint masks, normalized-time sync groups and editor-only node layout; Scene stores only the stable Graph asset reference. Graph 0.1 deliberately allows one state-machine node and terminal Clip children in Blend 1D so runtime instance identity stays unambiguous. Runtime samples every contributing clip into local transforms, applies ozz override/additive jobs and performs one final local-to-model conversion. The Graph state-machine node is authoritative over the legacy Scene state-machine field. Root motion is emitted only while the contributing clip identities, loop modes and secondary weight remain continuous; source/weight changes suppress one invalid delta rather than applying the previous time to a different clip.

Animation compression decisions use engine-owned plain evidence rather than leaking codec types into Graph or Scene. `noemancer.animation-compression/0.1` distinguishes estimated resident bytes from fixed-little-endian ozz archive bytes, records archive hashes and key counts, and compares two compiled clips over 257 fixed samples in local, model, 10 cm probe, skinning and root-motion space. The production default remains ozz runtime packing. Hierarchical key reduction is an explicit diagnostic candidate because the representative Mixamo clip reduced normalized keys without reducing the final runtime archive; ACL or another codec cannot be promoted until the same contract proves a material archive win and no sampling regression.

Animation source and Runtime identity are now separated by the version-controlled `noemancer.animation-clip/0.1` descriptor. Its FBX/GLB reference is a Cook-only build input, never a Package dependency. Cook hashes an immutable input snapshot and writes a content/recipe-addressed `noemancer.animation-cooked-artifact/0.1` envelope (`.animbin`) containing an exact little-endian header, bounded JSON manifest, ozz Skeleton/Animation archives, skin-to-runtime permutation and inverse-bind matrices; every section and the complete payload carry SHA-256 identities. Runtime validates ranges, schema/backend/endianness, fixed ozz archive tags/versions, the exact trusted-only archive layout before entering `IArchive`, the shared 64-joint GPU contract, section hashes, joint/track cardinality, finite scalars/matrices and expected Registry identity before transactionally publishing a Clip. Player never evaluates the descriptor branch, rejects packaged source FBX/GLB, and reports cooked loads/source decodes/offline compiles as structured evidence. Package preserves the Cook payload SHA-256, compares every probed file with its planned identity, re-verifies copied bytes before atomic directory commit, carries Cook-only source licenses as explicit notice roots, and rejects a derived artifact whose build input is `local-only`.

Geometry source and Runtime identity follow the same separation without sharing the animation envelope. GLB/FBX are decoded only from an immutable Cook snapshot; `noemancer.mesh-runtime-artifact/0.2` (`NMMESH02`) contains a bounded manifest, one independently meshoptimized `NMMSH001` section per material Primitive, engine-owned material/alpha/skin metadata and concatenated KTX2 images. The recipe includes schema, source identity, importer, target profile and partitioning/texture policy, so an implementation change invalidates cache identity. The Loader verifies exact little-endian ranges, section and payload SHA-256, canonical contiguous tables, vertex/index/skinning bounds, finite material values and bounded KTX2 headers before returning only `GltfMeshData`. Package requires the planned payload hash, invokes that same Loader before staging, rejects legacy meshbin and source GLB/GLTF/FBX, and carries fastgltf, ufbx, meshoptimizer and KTX-Software notices. Player never calls fastgltf/ufbx or meshoptimizer offline Cook for packaged geometry; Headless and Renderer status expose cooked-load/source-decode/offline-compile counts. This production boundary is closed and remains a prerequisite inherited by later profiles.

The Editor Canvas and `animation.graph.*` commands materialize the same Registry source, fingerprint and patch plan. Source commits carry a monotonic transaction ID; a Runtime reload failure may abort only that exact current transaction after verifying the source, never a different Editor/Agent edit. The Canvas authors bounded node creation/deletion, Blend 1D Clip connections, layout, layer weights/parameters and mask joint weights; projected ports, stable edges and hit targets are renderer-neutral views over that same source. Topology and parameter edits share candidate validation, compare-and-swap fingerprints, transactions and undo/redo rather than maintaining a GUI-only graph. In-process Editor commands share its live World/Registry. Standalone CLI/MCP defaults to a detached bootstrap Registry. `serve --project PATH` instead owns a persistent project World, Asset Registry and Project UI source session; MCP selects that explicit mode through `NOEMANCER_PROJECT`. This is a project-attached Agent process with durable source commits for its lifetime, not a remote connection to a separately open Editor process and not a cross-process shared undo journal.

Editor chrome is a projection over those authorities, not a second editor model. The Outliner publishes its active Edit/Play authority, bounded query and stable selection; the Inspector publishes the same selected entity, component count, property query and writability that its visible controls use. Presentation-only filters and component expansion remain local ephemeral state, while every mutation still enters the World or subsystem transaction API. Dear ImGui currently hosts the dockspace and these projections; retained RmlUi components may replace panels incrementally without changing their semantic identity or owning duplicated domain state. The retained runtime owns one primary game surface plus independently sized, density-aware named Editor surfaces. Each surface has an isolated DOM/context, cached renderer-neutral draw packet and explicit pointer/keyboard/text route; rendering one surface cannot overwrite another surface's packet. The Edit Inspector uses a dedicated sampled SDL_GPU color target whose size follows the Dock viewport; Editor window coordinates and IME caret coordinates map explicitly to and from `editor.inspector`. Its text, asset, scalar/range, boolean, enum, vector and color controls are generated from the same Semantic UI binding and constraints consumed by Agent observation. Stable group expansion is restored across projection reloads and appears in the same bounded observation, but its local toggle never enters the World action queue. The retained runtime emits a bounded `noemancer.retained-ui-actions/0.1` queue containing surface/document/node identity, action ID, complete binding, typed value and sequence. World-property bindings carry the source revision; the Runtime Adapter converts value-change intent back into the existing property plan/apply/receipt transaction and reloads the projection only after a successful commit. RmlUi never mutates World state directly.

The official Windows entry is `Noemancer Editor.cmd`, resolved from its own repository location and implemented by `scripts/launch-editor.ps1`; Platformer shortcuts remain validation-project entries. Launching without a project opens the branded Project Hub rather than exposing the renderer bootstrap fixture. `StartupHubModel` is plain Editor data with bounded recent-project status and a `noemancer.startup-hub/0.1` semantic projection; Open/New actions still enter the existing Project Workspace authority. Workspace creation owns the stable plain-data `starter` and `hybrid-pixel` presets: CLI `project create --preset` and Project Hub select the same request, while the latter atomically emits Project `0.2` with the validated Hybrid Pixel `0.1` profile. Presets do not own a second Scene or Project model. The native mark is an original flat vector asset and renderer-neutral primitive set. The hub owns no Project, World or Registry state.

Project UI source keeps one node language. Optional top-level `components[]` declarations reuse the existing node fields (`role`, `label`, `presentation`, `state`, `binding`, `actions`, `value`); `presentation.control`, `presentation.constraints` and `presentation.layout` remain the sole control/layout vocabulary. Declarations may `extends` another declaration and resolve base-to-derived with recursive object merge and array replacement, after which the node's own fields override the result. A node stores only source `componentRef` plus its local overrides. Runtime projection materializes the effective node and publishes `componentChain` provenance; the materialized resolution metadata and chain are runtime-derived evidence and cannot be written back as source observations. GUI requests and `ui.project.source.observe/edit` call the same `ProjectUiAuthoringSession`, including revision CAS, dry-run, atomic persistence, validation and undo/redo; a successful committed Agent edit hot-applies that authority's attached World.

Project HUD authoring now follows that same split. `ProjectUiAuthoringSession` is the source authority for the bounded `noemancer.ui-document/0.1`: it validates candidates, compares the expected source revision, detects external file replacement, atomically persists one canonical document and owns undo/redo. The Editor panel publishes requests and semantic drafts but owns no second HUD tree; Runtime hot-applies only a successful authority result to Edit and Play World. Authored revision is exposed as `sourceDocumentRevision`, while the materialized UI `revision` may also advance for input, gameplay or script state. An interactive action may declare `actions[].binding { kind: "script-callback", instanceId }`; World resolves both node and action from the canonical document, fixes the managed entrypoint to `OnUiAction`, and emits one revisioned receipt. RmlUi events and `ui.project.action.invoke` therefore enter the same Scripting Authority and a caller cannot supply an arbitrary callback name or script instance. Project-attached cross-process authoring remains future transport work; the standalone detached limitation above still applies.

Visual acceptance is an engine-owned evidence path, not desktop automation. `--capture-editor-frame` renders the complete ImGui Dockspace, sampled Scene texture and Retained panel textures into a swapchain-format offscreen target, downloads it after the final render pass and writes an image plus bounded quality sidecar. Scene-only `--capture-frame` remains separate so one run has one unambiguous readback authority; it uses the requested pixel dimensions and authoritative Scene Camera rather than inheriting Editor Dock geometry or the interactive orbit camera. A versioned reference contract supplies expected dimensions and bounded luminance limits to the same sidecar. `scripts/capture-render-reference.ps1` correlates that Golden capture with a Release CPU workload and content hashes in one immutable evidence manifest. Edit mode does not mount the former debug Inspector or game HUD over Scene View; Player mode owns game HUD projection.

Editor action icons are renderer-local vector primitives with stable semantic button IDs and text/tooltips, not private-use font glyphs. This keeps the interaction language consistent across platform fonts, locale fallback, hidden capture and offline distribution while leaving the underlying commands unchanged.

Edit World and Play World remain separate authorities during simulation. The Editor reads a bounded Play World hierarchy projection and the same declaration-driven Inspector document used by other semantic consumers; these views are read-only and never masquerade as Edit World state. Apply Back projects durable authoring fields from the Play World and produces a stable-ID entity/component diff against the captured Edit baseline. A user may select any non-conflicting subset of change IDs; the Engine rebuilds its canonical candidate from the baseline, rejects unknown/duplicate/conflicting selections and revision/fingerprint conflicts, dry-runs validation, then commits the candidate as one undoable Scene transaction. Physics caches, renderer resources, audio cursors and other subsystem-private state never enter that document.

Long-running work uses an engine-owned Job/Session object rather than blocking the GUI or inventing protocol-specific editor state. Asset jobs expose bounded progress, diagnostics and artifact URIs while hiding worker and local-path details. Import/Inspect rebuild isolated Registry snapshots with the existing importers; live revision checks stay at the Editor authority before reconciliation. Thumbnail plans are content/recipe addressed, use the existing PNG adapter, and cross into SDL_GPU only through a Runtime-owned bounded cache. Repair analysis is deterministic plain data; mutation remains in the host action authority. Managed debugging owns the hidden netcoredbg process, DAP correlation/event queue and bounded Editor projection; GUI and Agent controls call that same Scripting Authority. The adapter boundary accepts numeric or decimal-string DAP sequence values because the pinned production adapter emits both. Embedded-runtime attach remains a diagnostic path. The production workflow gives Runtime a separate packaged Player process under a kill-on-close Job Object: named ready/release events hold the Player after CoreCLR and project symbols load but before Scene script creation, then netcoredbg attaches, installs initial breakpoints and completes configuration before the Editor releases execution. DAP disconnect never owns Player lifetime; Runtime reaps the process explicitly, so a stopped game thread cannot freeze the Editor control surface or survive an Editor crash. Packaging remains a pure Engine plan plus a host-owned atomic staging commit, keeping filesystem mutation outside the package validator. Before planning a distribution, the Runtime host compiles the exact Debug/Release project configuration and deterministically regenerates the startup-scene Cook plan; cached artifacts may be reused, but an older or different Cook Manifest cannot be selected. Package closure starts from startup-scene asset IDs plus the Project's explicit `packagedAssets` roots for script/data-driven references, then follows Registry dependencies rather than redistributing every cache output.

Texture Cook keeps source identity separate from execution format. PNG import infers a bounded semantic profile (base color, normal, linear data, emissive or UI), then plans KTX2 BasisLZ/UASTC output whose cache key includes source bytes, recipe, semantic, color space and quality. Registry assets may author `streamingPolicy { mode, importance, priority }`; the validated values survive Cook/Package and remain engine plain data. Runtime asks SDL_GPU whether BC7 sampling is supported and keeps libktx/codec types private. A streamed KTX2 starts as a physically smaller four-level mip-tail texture rather than a full allocation. A pure deterministic planner combines screen footprint, visibility aging, hysteresis, authored importance/priority, per-frame copy budget and a resident-allocation budget. Upgrade or downgrade creates a replacement mip tier whose authored first level is GPU mip zero; the complete retained tier is uploaded from persistent bounded staging because cross-base texture copies are not portable across the supported SDL_GPU drivers.

All current authored or editor-derived sampled texture consumers converge on one Runtime-private `TextureResourceTable`. A handle contains slot identity plus an identity generation; each committed physical replacement increments a separate resource generation. Registry KTX2 Sprite/material channels, source PNG Sprite channels, imported glTF PBR images, RmlUi game/Inspector textures, the Inspector sampled target and Asset Browser thumbnails register stable ID, semantic, owner, source, residency and bounded allocation metadata. Upload/replacement remains pending while the caller-owned command buffer is recorded; successful submit commits the generation and retires the previous resource, while cancel or submit failure restores the prior entry and releases the rejected allocation. Renderer Status v25 publishes the bounded `noemancer.texture-resource-table/0.1` projection alongside `noemancer.texture-residency/0.3`, Sprite mixed-material counters and Hybrid Pixel presentation/VFX/post evidence. Renderer fallback textures, IBL derivations and Render Graph/history/shadow targets remain private execution resources rather than being mislabeled as authored assets. Current VFX billboards are procedural and do not sample a texture; any future flipbook, sprite or map input must enter this table before it can be considered a production VFX texture path.

Sprite material authoring remains one extension of the existing Sprite authority. `noemancer.sprite-asset/0.2` keeps the optional material document and adds stable lit/unlit, metallic/roughness and receive/cast-shadow intent beside normal, emissive-mask and depth/height channels. The Codec is the sole dependency projection used by Registry inspect, Cook and Package closure; a legacy Sprite with no material maps explicitly to unlit/no-shadow behavior. Render World v14 carries only engine plain data. Runtime resolves all Sprite channels through the same Texture Resource Table, packs a 224-byte instance and evaluates the existing directional and clustered Point/Spot lighting, CSM/local shadow maps and indirect-light/AO target; there is no second 2D renderer or Profile-specific light database. Alpha-cutout Sprite casters enter the existing per-cascade/per-face shadow fingerprint and cache, so a steady frame may correctly report zero submissions together with non-zero avoided work. Final hidden captures publish the exact `render.world.final` snapshot consumed by the renderer as bounded evidence instead of mirroring World state every frame.

Large Sprite/Tilemap production remains bounded at source authority rather than at an Editor-only importer. Sprite parsing rejects source, frame, clip and reference counts beyond explicit limits; its production report computes deterministic reference reuse and the exact union/overlap/free area of the authored texture. A renderer-neutral multi-page planner uses stable frame identity and deterministic shelf placement, then the Registry Cook copies frames into transparent page surfaces and independently encodes every page as KTX2 through the existing libktx/Basis Adapter. Page content/layout/recipe/profile/compression/actual-worker identities address a bounded disk cache; the emitted `SpriteAtlas` manifest retains the canonical `Sprite 0.2` authoring document, stable frame-to-page bindings and SHA-256 page identities. Cook manifest outputs flatten the binding artifact and pages into an acyclic Package closure with inherited license/streaming metadata. Runtime registers the embedded authoring document, applies a runtime-only CAS page overlay, and Renderer resolves the derived page Asset ID and page-local rectangle without changing the source persistence format or exposing KTX types. JSON projections cap pages and placements, and `asset.sprite.pressure` exposes a smaller capped comparison for Agent decisions. Tilemap parsing, collider bake, compiled Chunk visibility and incremental stroke receipts share explicit layer/Chunk/Cell/collider ceilings. Each compiled Chunk owns a deterministic packed plain-data range; local edits report dirty/rebuilt/reused/created/removed Chunks, uploaded cells/bytes and unchanged range reuse without exposing an SDL or native GPU handle. Registry `asset.inspect`, Cook receipts, `asset.sprite.pressure` and `render.tilemap.pressure` are bounded semantic projections of these authorities. They distinguish source-layout, encoded artifact and residency facts from real GPU timing; texture arrays still require measured benefit and are not inferred from scale alone.

KTX2 Cook remains behind the engine-owned plain-data Adapter. Its result projects cache identity, resolved worker count and measured input-fingerprint, plan, mip generation, libktx load, Basis encode, write, verification and cache stages. Worker selection is capped at eight; one worker remains the reproducibility-preserving production default, while explicit or automatic parallel execution is currently an Adapter/probe option rather than a Registry Cook setting. Worker count participates in the in-process cache key, and cache hits preserve only the current request's timings. A fixed Release 4096×4096 Basis-LZ probe showed that eight workers preserved the payload fingerprint but reduced first Cook only from 24.698 s to 20.853 s on the measured host; Basis encode remained the dominant stage. That single-host result is evidence for optional parallel Cook, not permission to silently change cross-machine artifact identity.

Hybrid Pixel VFX remains an execution mode of the existing VFX authority, not a second particle runtime. `render.sprite` graph nodes default missing 0.1 fields to `pixelAlignment=profile`, `sizeQuantization=profile` and `sampling=profile`, while explicit `none/none/linear` preserves Raster-style behavior. Render World v15 carries those values as plain data into the unchanged GPU lifetime pool, blend grouping, global alpha sort and dual indirect draws. VFX ABI 0.7 packs blend and graph policy bits separately; the group kernel masks only the blend bit. A 128-byte camera constant appends virtual extent, world-units-per-pixel and active Profile flags. The vertex shader snaps current and previous centers to the same virtual pixel centers and quantizes billboard size, so motion vectors remain coherent; the fragment shader selects hard pixel-center coverage only when both Profile and graph request it. `noemancer.hybrid-pixel-post-process/0.1` is the renderer-neutral strategy: Hybrid disables temporal jitter/history, retains the same exposure Render Graph pass but writes deterministic unity, and runs bounded Bloom and spatial AO in the virtual extent before nearest integer presentation. Disabled Profile returns the existing TAAU/adaptive-exposure Raster policy.

Hybrid Pixel Profile authoring is a Project transaction, not Editor-owned configuration. `ProjectHybridPixelAuthoring` holds the optional engine value, manifest path, monotonic revision and bounded undo/redo history; every apply, remove, undo and redo validates with `HybridPixelProfileCodec`, compares the expected revision, writes a sibling temporary Project `0.2` manifest and atomically replaces the source before publishing memory. It changes only `hybridPixelProfile`, preserving Input Actions and unknown project fields. `HybridPixelProfilePanel` owns only a transient draft and projects the same revision/profile into field diagnostics, virtual-to-physical integer-scale/letterbox preview, stable action IDs and a bounded semantic state. The Runtime Adapter consumes its plain-data request and hot-applies the Renderer only after a successful non-dry-run commit. Visible ImGui controls and `projectSettingsHybridPixelProfile` Agent observation therefore share one snapshot/draft/receipt path; neither may mutate the manifest or cache a second authoritative Profile.

Local-light shadow scalability stays within the same Scene `LocalLight.castsShadows` authority. Runtime deterministically assigns the bounded eight-layer D32 array by camera-weighted luminous influence, then fingerprints each selected light face from stable light identity, view-projection, the ordered visible caster set, transforms, cutout state, geometry ranges and skinning palettes. An unchanged face preserves its existing array layer and records no render pass; target recreation, quality change or any relevant light/caster change invalidates it. `low`, `medium` and `high` select 512/768/1024 layer resolution and bounded light budgets before GPU allocation, while Renderer Status v11 exposes current and cumulative cache evidence. This is an execution cache only: it does not duplicate Scene, World or Semantic State Plane state.

Directional CSM uses the same execution-cache principle without introducing persisted cache state. Each of the four D32 cascade layers fingerprints its stable light matrix and ordered visible caster inputs, including transform, cutout/material flags, geometry/GPU resource identity and skinning pose. A matching fingerprint preserves the layer and records no cascade render pass; target recreation, camera/light matrix motion or a relevant caster change invalidates only the affected layer. Renderer Status v14 exposes rendered/cached cascades, cumulative hits/misses and avoided submission estimates, while Commercial Raster Reference 1.5 requires first-use generation followed by four-layer steady-state reuse on D3D12 and Vulkan.

Package configuration is a verified input, not a display label. The Windows host resolves the native executable and ManagedHost from the exact Debug/Release configuration requested by the target profile and rejects missing or cross-configuration fallback. The generated Game Profile carries explicit bundled/unbundled runtime requirements so an installer, CI worker or Agent can reason about clean-machine readiness without inspecting PE imports ad hoc. Signing, installer execution and machine mutation remain outside the pure Engine planner and enter only through host-owned adapters.

Release packages use app-local .NET hosting: the pinned major-compatible HostFXR and `Microsoft.NETCore.App` payload are redistributed under `runtime/dotnet` with their license texts, and runtime discovery preserves package-local priority before developer and machine roots. `DOTNET_ROOT` is derived from the selected HostFXR rather than compiled source paths, making the managed script host relocatable without a machine-wide .NET prerequisite. The Noemancer source/runtime license is Apache-2.0; project-owned content keeps a separate `LicenseRef-Noemancer-project` identity. Every redistributed entry and every statically linked Runtime/Cook provenance root closes through a deterministic license ledger containing ownership scope, SPDX/custom identity, source URI, entry references and required roots. Pinned source license texts for SDL, Flecs, nlohmann-json, Dear ImGui, ImGuizmo, LodePNG, miniaudio, Jolt, FreeType, RmlUi, Lato, HarfBuzz, ICU, ozz-animation, ufbx, fastgltf, meshoptimizer and KTX-Software are staged under `licenses/runtime/` and appear in generated `THIRD_PARTY.json`/`NOTICE.txt`; local-only Mixamo evidence inputs never enter a distribution. The bundled Lato face resolves relative to the Player executable before development fallbacks, so UI startup does not depend on a build-tree path.

Process diagnostics are installed before Runtime CLI dispatch. Fatal terminate, abort, Windows SEH, invalid-parameter and purecall paths suppress OS/CRT modal reporting, emit one bounded JSON record to stderr and, when a report directory is configured, persist a `noemancer.process-diagnostics.v1` sidecar plus a Windows minidump. Runtime defaults to `%LOCALAPPDATA%/Noemancer/Diagnostics`; `NOEMANCER_DIAGNOSTICS_DIR` provides an explicit automation/package probe override. This is a diagnostics artifact boundary, not persistent World state, and it never changes gameplay authority.
Release packages also stage the official VC143 app-local CRT selected from the build toolchain's redistribution directory. The Game Profile records its exact redist version and bundled status; `runtime.native_dependencies` then observes the Windows loader result for the required MSVCP/VCRUNTIME modules and distinguishes package-local resolution from machine fallback. Distribution intent and runtime proof therefore remain separate, correlatable evidence. Public signing, installer UX and an independent clean-machine matrix remain release-channel gates rather than hidden assumptions in Package planning.

Project workspace creation is an Engine service shared by Editor and CLI rather than UI-owned filesystem code. It validates an absolute non-existing destination, writes a complete project into a bounded sibling staging directory, and commits with one directory rename. The generated workspace contains a Project manifest with explicit version-control-friendly Input Actions, canonical bootstrap Scene, project-owned Asset Registry for the referenced built-in fixtures, compile-ready .NET project and starter behaviour. Runtime project switching stages Project/Scene/Registry/script configuration before replacing the Editor context; the same validated Input Action definitions configure Edit World and each independent Play World. The Editor resets selection, undo history and saved-scene baseline only after the new project is accepted. Dirty Scene close requests are coordinated through Save/Discard/Cancel instead of letting SDL window events bypass the authoring authority. New Scene starts from an asset-free Root/Camera/Sun document with a fresh stable identity and remains dirty until Save As. Recovery discovery is a bounded, project-relative projection over validated `.noemancer-recovery` sidecars under `scenes/`; applying one revalidates containment and loads it against the current target-file baseline as unsaved changes, so the recovery file never silently overwrites the source.

Project script authoring remains source-owned rather than embedding a second IDE model. The Scripting Authority publishes a bounded, project-relative C# document catalog and build/source fingerprints; the Editor provides explicit project/file launch actions, while a Runtime-owned adapter canonicalizes the target, rejects paths outside the active project and delegates to an installed code editor or Windows file association. Source preview and debugger breakpoint selection are separate intents. Editor build completion crosses into the application loop as an event: a successful Debug build prepares the independent Play World runtime at a main-thread safe point, then its existing collectible AssemblyLoadContext migrates script state on the next managed callback. A failed Edit or Play compile retains the previous Play assembly, remains visibly dirty, and suppresses repeated automatic retries for the same failed fingerprint without blocking a manual retry.

Managed gameplay reads a bounded cached `EntityView` projection with stable ID, name, optional position, component IDs and tags, plus typed views of its own velocity, CharacterMotor2D decision and Sprite playback; project code does not parse engine-private ECS storage or repeatedly reparse the same callback JSON. Input actions are likewise cached for one callback. Managed position, linear-velocity and Sprite-visibility commands remain plain data and converge on the existing World property authority. Sprite clip/facing changes use the Runtime-owned `sprite.playback.set` command: it validates the registered Sprite asset and clip, is idempotent when the requested state already matches, emits a non-undoable semantic delta when it changes, and never rewrites the canonical Scene. Scene property transactions remain the authoring path; transient animation cursors remain Play World state. This reuses the existing Sprite/Atlas playback and renderer rather than adding a second managed animation runtime.

Runtime Prefab spawn/instantiate/despawn rebuilds a validated candidate from the live authoring projection so moving Transform/Velocity state is not rolled back by a gameplay lifecycle command. A cloned `ManagedScript` receives a stable instance ID derived from the new entity, despawn releases script instances and removes Gameplay Ability actors/effects that reference the entity, and gameplay lifecycle reloads preserve the Edit history boundary. This is the correctness-first small-world path; it does not claim pooled O(1) spawning. A future pooled lifecycle or native overlap query is introduced only against a representative migration workload and must preserve the same stable IDs, project C# ownership and semantic receipts.

Portable Save and Replay are Engine-domain documents, not raw memory dumps. Save `0.2` joins the runtime-authored durable Scene projection, simulation Tick and managed members explicitly marked `[ScriptState]`; restore validates stable instance/entity/type identity and uses the same managed migration contract as hot reload. Replay `0.2` includes its initial Save plus logical input samples stamped relative to fixed simulation ticks, then restores and advances the ordinary Input, physics, gameplay and script path under strict sample/tick limits. C# emits a bounded `gameplay.persistence.request`; World validates and queues plain-data requests, while the Runtime-owned `GamePersistenceStore` maps stable project/slot IDs into the platform user-data directory, rejects traversal/symlinks and wrong schemas, enforces byte limits, and commits through a sibling temporary file plus atomic replacement. Completion returns as the ordinary `gameplay.persistence.completed` event, so scripts, GUI and future Agent surfaces can observe one authority without exposing filesystem handles.

A distribution contains `bin/`, `config/`, `content/`, `managed/` and `licenses/`. The renamed Runtime executable discovers its sibling Game Profile when launched from a package and enters Player mode: it loads the packaged startup Scene, normalized Input Actions, optional project HUD, package-local Asset Registry, project assembly and packaged ManagedHost, then advances the authoritative World and presents only the game surface. Game Profile `0.4` adds the optional canonical Hybrid Pixel Profile to the `0.3` asset-registry/packaged-root contract; `0.1`–`0.3` remain readable. The package registry restores stable Asset IDs, types, hashes, licenses, dependency edges and paths relative to `content/assets/`; Runtime converts audio records into its private miniaudio source catalog and registers the same descriptors in World, while Sprite/Tilemap parsers consume the same Registry authority. SDL3 emits generic stable keyboard/gamepad source IDs and owns device lifetime; dead-zone and binding policy remain project data. A project HUD is a validated `noemancer.ui-document/0.1` asset packaged under `content/`; `script-state`, `input-action` and `gameplay-attribute` bindings are materialized from the same World authorities exposed by `ui.project.observe`, then the same document enters RmlUi. Managed callback public state is retained as plain data by the Scripting Authority rather than scraped from pixels or native handles. Editor panels and the semantic Inspector overlay are not part of the Player shell. Source-project compilation and packaged prebuilt-assembly loading are separate Scripting Authority entry paths; both converge on the same managed callback ABI and World command buffer.

Shader compilation has one versioned source contract rather than call-site binding guesses. `noemancer.shader-artifact-source-contract/0.1` enumerates every HLSL stem, stage/profile/entrypoint, SDL resource counts and Compute thread group. The pinned DXC produces DXIL and SPIR-V; a deterministic `noemancer.shader-artifact-manifest/0.1` records source, compiler, arguments, artifact bytes and SHA-256. The build then reflects DXIL container/PSV data and independently parses SPIR-V instructions/decorations to prove stage, entrypoint, resources, thread group and cross-backend logical ABI before the Runtime target is accepted. Runtime owns one private manifest loader used by Scene, GPU visibility, VFX and retained UI: it rejects unsafe paths, schema/resource/stage drift and byte/hash mutation before SDL_GPU object creation. Packaged Players resolve `../shaders` beside `bin/` before the compiled development fallback. The Package service parses the same validated Manifest and stages only its declared DXIL/SPIR-V paths plus Manifest/Reflection metadata; it never globs a possibly stale build directory. The current distribution therefore closes exactly 58 backend binaries for 29 HLSL entries, including the Sprite alpha-cutout shadow vertex path, and cannot silently borrow or ship an obsolete artifact.

## Semantic-first editor

Pixels are evidence, not the only interface. User-facing controls and viewport selections expose stable semantic identity, focus/hover/selection, value, action, bounds and source. The Engine Semantic Observation Graph joins focused slices of:

- UI semantics;
- visible scene entities and screen-space bounds;
- render passes/resources/pipelines and diagnostic relationships;
- on-demand image/depth/object-ID/normal evidence.

The graph is an engine capability consumed by Editor, CLI, MCP, accessibility and tests. It is not an MCP feature and is not serialized in full every frame.

## Runtime and performance rules

- Interactive and Headless execution share World and simulation behavior; hardware adapters may differ.
- Render, audio and build work must not be coupled to the editor frame when independent scheduling is required.
- Hot paths use native data and batched boundaries. JSON is for control/observation, not per-particle or per-entity inner loops.
- Performance claims require a fixed workload, quality, hardware, compiler, driver and revision.
- Runtime performance evidence uses `noemancer.performance-evidence/0.1` for an immutable internal observation of warm-up/sample boundaries, end-to-end main-thread frame wall time, process memory and complete Renderer Status. GPU execution time is never inferred from CPU submission: the Windows harness pins official PresentMon 2.4.1, upgrades the merged artifact to `0.2`, and can require external GPU telemetry as a strict gate. A host that yields no Present rows records that limitation instead of inventing a value.
- Representative animation/physics evidence uses a generated but ordinary Scene containing 64 instances of the registered Mixamo/ozz asset and 256 persistent Jolt dynamic bodies. The workload runs through the Player-style 1920×1080 surface so Editor Inspector construction cannot contaminate its frame budget. Simulation views intentionally omit render-only skeletal palettes; the one Render Extract view samples each visible pose once. Root-motion sampling is conditional on `rootMotionMode=apply`, so an ignored root cannot cause hidden duplicate ozz jobs. Renderer Status v12 reports skinned instance, Draw Item and joint-matrix counts, and `noemancer.animation-physics-evidence/0.1` binds these counts to CPU distributions and a hidden visual artifact.
- Animation compression evidence decodes and compiles outside the timed region, then alternates baseline/candidate order across 120 frames of 64 preloaded pose samples. It records real runtime archives rather than source-container size and gates the optimizer's model-space translation, 10 cm probe and root-motion error at 1.1 mm. Local rotation and matrix-element deltas remain diagnostics because the ozz optimizer's declared contract is hierarchy-aware positional error. Timing is reported but not promoted from one noisy run; the production mode changes only when repeated evidence also proves a material archive or sampling benefit.
- The opaque/shadow instancing ABI groups compatible geometry, texture bindings and raster state while carrying color, metallic/roughness, emissive, alpha/occlusion data and identity per instance. Static Draw Items do not own empty 64-joint palettes; skinning history is retained and materialized only for genuinely skinned draws.
- Static opaque submission has an optional GPU-driven execution path without creating a second Scene authority. Render Graph v11 retains the GPU visibility pass and its instance, batch, compact-index and indexed-indirect buffers alongside the expanded post-process DAG. Runtime groups only identical geometry/texture/raster state, persists the engine-owned instance ABI, cycles buffers at frames-in-flight write boundaries, computes six-plane frustum visibility and consumes the compacted index stream with one indirect draw per compatible batch. Skinned, transparent, small, overflowed or unsupported cases retain the direct CPU-cull/16-instance path; initialization failure disables the optional capability and a frame-local copy/compute failure clears GPU eligibility before opaque recording so geometry cannot disappear. Renderer Status v25 retains `noemancer.gpu-visibility-readback/0.2`: only an explicit evidence run copies the bounded indirect command range and compact visible-index stream after draw consumption in the same command buffer, acquires a dedicated fence, then verifies per-batch counts and exact normalized index sets against the CPU frustum oracle. The evidence reports portable set hashes plus invalid-count, count-mismatch, out-of-range, wrong-batch and duplicate counters; any non-zero counter or set mismatch fails the run. This readback is forbidden in formal performance sampling and never runs in the steady-state path. The versioned partial-visibility workload authors 25–50% of stress instances outside the frustum so all-visible agreement cannot pass accidentally.
- Stable batching uses engine-owned identities, never SDL/GPU pointers, for its reusable key: geometry, material and raster identities/generations plus an ordered texture binding list of Shader-slot semantic, stable resource ID and resource generation. Shader-slot semantics such as `normal`, `metallic-roughness` and `occlusion` are explicit binding identities; they are intentionally independent from a resource table's broader storage semantic such as `pbr-linear-data`. Texture-table transitions advance the effective generation, while invalid/stale handles require an explicit fallback stable ID, so a replacement cannot silently reuse an old batch. An invalid per-draw identity makes only that draw GPU-ineligible and routes it through the existing direct path; it never aborts frame recording. Draw/history identity remains separate from the resource key. The bounded cache canonicalizes eligible opaque/unskinned inputs by key and draw ID, preserves logical stable slots, and reuses the canonical linear topology when the frame topology fingerprint is unchanged; key, eligibility or draw-identity changes rebuild the plan, while small and capped/overflowed groups remain on the CPU path. Renderer Status exposes this diagnostic as `noemancer.gpu-stable-batching/0.1`; it is separate from the submission ABI.
- On topology reuse, the fixed-stride instance payload is compared as bytes and adjacent dirty items are coalesced into upload ranges. Only the current active linear range is packed and uploaded, so a removed tail is retired by the active count instead of producing a stale/out-of-bounds transfer. A topology rebuild deliberately forces a full current-range instance publication; the batch table uploads only when its bytes change. Indexed-indirect commands remain reset/uploaded each frame because the visibility shader atomically increments each batch's instance count; this is an intentional counter-reset boundary, not a claim of zero command traffic. The stable-batching report separates instance, batch and command bytes and records topology reuse/rebuilds, stable-slot reuse/moves and dirty ranges.
- The static opaque submission ABI is `noemancer.gpu-driven-static-opaque/0.4`: `GpuDrivenInstance` is 224 bytes (current/previous model, per-instance material/alpha/occlusion/identity and bounds), `GpuDrivenBatch` is 16 bytes (candidate and visible ranges), and the indexed-indirect command is 20 bytes. The visibility kernel rejects dispatch candidates outside the declared count, rejects invalid batch IDs and bounds each batch's visible write by its candidate count. The GPU vertex shader validates draw metadata against the fixed instance capacity and validates each compacted instance index before reading the instance buffer, returning a clipped vertex for invalid metadata rather than forming an unchecked buffer access. The readback contract remains the separate `noemancer.gpu-visibility-readback/0.2` evidence ABI and is not part of steady-state performance.
- Local lighting is one stable `LocalLight` domain component rather than separate backend-flavored Point/Spot types. Its authoring values use explicit kind, linear color, luminous power in lumens, range/source radius in meters, direction and cone angles; Scene persistence, live World, Render World v13, declarative Inspector, generated C# Schema and semantic observation share that authority. The current Forward+ path deterministically assigns up to 256 local lights into a 16×9×24 logarithmic-depth grid with a 64-light cluster bound, uploads compact ranges/indices through SDL_GPU graphics storage buffers, and evaluates Point/Spot PBR on GPU. Assignment is CPU-built until evidence justifies a Compute migration. Directional CSM remains separate. Shadow-casting local lights compete for a quality-tiered eight-layer D32 array: one Point cubemap-equivalent plus up to two Spot layers at high quality. Selection ranks camera-weighted luminous influence, resolves ties by stable Light ID and retains separate kind budgets. Each chosen face fingerprints its stable light/matrix and visible caster geometry, transform, cutout and skin state; unchanged layers skip the render pass. This bounds memory and work while publishing selected IDs, cache hits/misses, avoided submissions and invalidation policy.
- Built-in prototyping geometry must be suitable for visual diagnostics: the sphere is a smooth 32×16 UV mesh rather than the former 20-triangle icosahedron. Commercial content still enters through the ordinary imported/cooked mesh path; reference-scene geometry does not become a second asset system.
- Commercial material coverage uses a small CC0 GLB generated deterministically by `scripts/generate-material-reference-asset.ps1`. Its OPAQUE, MASK and BLEND cards carry embedded base-color, normal, metallic-roughness, occlusion and emissive PNGs, enter offline fastgltf decode and `noemancer/meshbin/0.2` Cook, then use the same Player Loader, sRGB/linear texture allocation and Forward PBR submission as packaged project content. The reference contract checks renderer feature and geometry-loading counts as well as pixels, so a missing binding or accidental source decode cannot pass merely because the rest of the scene remains bright.
- Commercial Raster Reference 1.8 and Render Graph v11 retain the four-level RGBA16F dual-filter Bloom pyramid and explicit indirect-light boundary to Forward PBR. Lit opaque output writes total HDR plus a separate diffuse/specular IBL target; the BRDF uses the split-sum LUT for bounded roughness-aware GGX multiscatter compensation. Eight-direction, four-step horizon AO runs at half resolution, then passes through horizontal and vertical depth/normal-aware bilateral filters. The HDR composite reconstructs `direct + emissive + indirect * AO`, so screen-space AO cannot multiply direct lights or emissive output. Sprite, unlit and VFX paths write zero indirect contribution. Transparent lighting is applied after the opaque AO composite and retains the same six-target ABI without retroactively treating transparency as screen-space occlusion.
- Renderer Status v25 identifies the AO technique, complete display path, Sprite mixed-lighting state, Hybrid Pixel projection, VFX pixel policy and controlled post-process domains. Tone mapping consumes graded scene-linear Rec.709 after exposure and Bloom, transforms through the standard ACES input matrix, fitted RRT/ODT response and ACES output matrix, bounds the result to Rec.709, then applies an explicit sRGB transfer because the SDL target is `RGBA8_UNORM` rather than an sRGB format. Non-finite/negative HDR and grading inputs are bounded before nonlinear operations. Reference 1.8 preserves Bloom and AO fixtures and adds reflection-isolated emissive gray, RGB/CMY and HDR shoulder patches with normalized interior ROIs. The offline verifier decodes the captured BMP as sRGB, measures linear-light gray monotonicity/cast, six expected RGB/CMY channel signatures, shoulder compression/clipping and global non-black state. Hidden AO enabled/disabled captures remain a separate linear-luma A/B contract; D3D12 and Vulkan use the same authority and `--disable-ambient-occlusion` remains evidence-only.
- A fixed simulation tick materializes one bounded World View and reuses it across systems. It refreshes that view only after a mutation that can affect a later consumer; transform-delta baselines are restricted to entities whose active components can move them. Render-only entities therefore do not pay repeated all-world copies or simulation transform bookkeeping, while platform, character, animation, physics, velocity and camera-follow ordering remains explicit.
- Mature kernels are adopted before expanding temporary implementations. Noemancer owns adapters, stable semantics, authoring, diagnostics and integration evidence.
- Input authoring follows the same Authority split: project JSON stores logical action and stable source IDs; `ProjectInputAuthoring` owns validation while `ProjectInputEditSession` applies revision-CAS requests to a candidate, atomically persists it, then publishes canonical actions. The visible Editor Project Settings panel and Agent snapshot project the same stable retained nodes and emit intents; successful receipts hot-apply the same actions to Edit World and an existing Play World. The SDL Runtime adapter alone converts physical codes/device instances into canonical IDs and bounded capture/device observations. Headless `--input-sample` uses the ordinary World injection/evaluation path and publishes action state for project/package acceptance. SDL enums and handles never enter project persistence or Agent contracts.

## Product profiles

Profiles compose general engine capabilities; they do not fork the Runtime. `Hybrid Pixel` is the active profile after the production loop, Lumen Run vertical slice and Commercial Raster material/post-process closure. Project `0.2` optionally embeds one engine-owned `noemancer.hybrid-pixel-profile/0.1`; Game Profile `0.4`, Editor/Agent observation and Player consume that same value. When enabled, the existing Renderer uses the authored virtual extent as render/post extent, disables temporal jitter/history, derives orthographic height from pixels-per-unit, snaps Camera/Sprite/Tile Cell only in the freshly extracted Render World, and nearest-blits into a deterministic integer-scale/letterbox physical rectangle. Physical picking maps through the same half-open presentation plan and ignores black bars without creating a readback. The canonical Scene/World, physical UI surface and normal Raster path remain unchanged authorities. Sprite normal/depth/material and mixed 2D/3D lighting flow through the existing Registry/Texture Resource Table/Light/Shadow path; pixel-aligned VFX and bounded post policy reuse the existing VFX GPU lifecycle and Render Graph; Profile editing is an atomic Project transaction rather than Editor-owned state.

The production composition is now a closed contract rather than a list of isolated features. Headless source projects and packaged Players publish `noemancer.runtime-production-state/0.1`, a bounded semantic projection of the active Profile, authored Input Actions, materialized project UI and managed-script state/execution proof. Acceptance removes only execution-location details such as HostFXR and assembly paths before fingerprinting; it does not infer behavior from screenshots. That projection complements, rather than duplicates, Render World v15 and Renderer Status v25 fingerprints. The disposable Semantic 2D Character Rig/Bake-to-Pixel experiment proved deterministic stable identities and one-frame edit isolation for a 2×2×4 workload, but its canonical source was larger than the measured direct-frame description. It therefore remains an unregistered Cook-side prototype with no Runtime path, Registry kind or production persistence schema; production adoption stays deferred until a larger real workload reverses that result and justifies an ADR. The external HD2D slice proved that project C#, Sprite/Tilemap, mixed 2D/3D lighting, VFX and UI can remain project-owned through source and packaged execution.

Process startup now publishes one bounded `noemancer.runtime-startup-telemetry/0.1` event from the process-entry clock. It records owned phases and only frames 1, 3 and 64; it is diagnostic evidence, not a second profiler or an always-growing event stream. The fixed HD2D 1-frame comparison measured Debug 16.45 s versus Release 1.69 s: Debug cost was dominated by retained UI initialization (7.80 s) and first-frame work (7.12 s), while project managed build was 12.65 ms and Asset Cook 0.01 ms. The official Editor launcher therefore uses Release for interactive product work and keeps explicit `-Config Debug` for native debugging. Managed project compilation separately uses a content-addressed cross-process cache keyed by project sources, public managed API, build props/targets and pinned compiler identity; entries are hash-verified, atomically published and globally bounded. These mechanisms expose the development loop without weakening project or renderer workloads.

The next AI-native boundary is a live Editor session transport. It must attach tools to the Authority already owned by a running visible Editor rather than constructing a parallel `serve --project` World. Session discovery, local authentication, process ownership, revision checks, bounded observations and durable transaction receipts must be defined before exposing mutation. The transport is an adapter over existing commands; it must not create a second World, Undo journal or semantic database.
