# 文档权威性与维护规则

## 当前权威入口

1. `current-state.json`：供 Agent 快速路由的机器可读状态。
2. `architecture.md`：当前仍成立的系统边界与不变量。
3. `development-plan.zh-CN.md`：唯一开发排期。
4. `first-acceptance-status.zh-CN.md`：已经取得的验收证据与真实缺口。
5. `adr/README.md` 与 Accepted ADR：已采纳的具体架构决策。
6. `research/`：带日期的历史研究，不代表当前实现或当前排期。

## 面向读者的说明

- [`rendering-explained.zh-CN.md`](rendering-explained.zh-CN.md)：用非渲染专业读者也能理解的方式说明当前引擎完成度、整帧渲染流水线、已成立能力与真实缺口。它是解释性入口，不改变以上权威关系。

若内容冲突，真实代码与自动化证据优先；随后应立即修正前三份权威文档，而不是依赖读者自行判断。

## 防止过时信息误导开发

- 改变后端、所有权、公共 Schema、模块依赖或开发优先级时，在同一提交中改写对应旧描述。
- 已完成的“下一步”应删除或改成完成态；不能只在文档末尾继续追加进展。
- 研究报告保留历史判断，但若结论被推翻，要在开头标明 superseded，并链接替代决策。
- 开始一个新开发批次前，只读取当前任务相关的权威入口和必要 ADR；不要把所有历史研究全文当作最新要求。
- 验收数字注明后端、场景和时间点，不把一次本机结果外推为跨平台结论。
- 开发计划和能力状态不保存逐提交流水账；Git 历史承担历史记录。2026-08-21 以前的长版计划/验收日志可从 revision `3e15f66^` 查阅。

## 验证节奏

开发速度优先采用分层验证：边界明确的 Worker Lane 可以连续完成相邻改动，不要求逐文件编译；集成批次结束才编译受影响目标并运行最小相关测试集。里程碑、发布或跨系统公共契约变化才执行全量 CTest。只有 Agent ABI、命令注册、MCP Adapter 或里程碑变化才额外启用 MCP smoke。GPU 隐藏捕获只跟随渲染相关变化或视觉验收，双后端验证只跟随跨后端渲染风险。

新增测试以风险为依据：优先保护持久化格式、公共 Schema、并发/所有权、事务、解析器、崩溃修复和曾经出现的回归；不为文档、重命名、简单接线或已被邻近测试覆盖的实现细节机械新增 case。

修改架构、计划、ADR 或研究分类后运行 `scripts/audit-governance.ps1`。它只检查权威路径、历史标记、篇幅预算、已退休措辞和本地链接，不编译引擎，也不进入普通代码内循环。

## Agent 协作文档规则

- 开发期 Sol/Luna 分工是仓库执行流程，不属于 Runtime Agent、MCP 或公共 Agent ABI。
- 权威文档默认由主代理在集成边界统一改写。Worker 可以提交证据和建议，但不与其他 Writer 同时编辑同一权威文件，也不把临时判断写成当前架构。
- 用户级自定义 Agent 文件持有具体模型和推理档位；仓库只引用稳定的 `luna_worker` 角色名，避免模型升级变成产品架构变更。
- Ralph Loop 由 Codex `/goal` 持续恢复，不是定时自动化或递归 Prompt 脚本；它始终受当前用户目标、权限、里程碑与停止条件约束。
- 测试门禁按集成批次执行；各 Worker 不重复运行全量 CTest。涉及依赖、CMake 或公共构建配置时，由主代理在集成后重新 configure 并执行升级后的对应门禁。
